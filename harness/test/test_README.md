# harness/test/ — Harness 跑通验证

四张实机截图，证明四件事：agent loop 能**自主**调工具、能**自主选择不调**工具、
前后端**解耦**（事件实时推送）、YOLO 能被当作插件**跨解释器**接入。

## 环境

| 项 | 值 |
|---|---|
| 模型 | qwen2.5:7b（Ollama 本地，`127.0.0.1:11434`） |
| 运行时 | 系统 Python 3.14，**仅标准库、零第三方依赖** |
| 前端 | 终端 CLI ｜ 浏览器（SSE，`127.0.0.1:8000`） |
| 工具 | get_time ｜ http_get ｜ yolo_detect（子进程桥接到 `D:\envs\yolo`） |
| 日期 | 2026-10-11 |

## 用例

| # | 验证点 | 输入 | 预期 | 结果 | 截图 |
|---|---|---|---|---|---|
| 1 | 工具调用主链路 | `--ask "北京现在几点？"` | `[调用工具] get_time` ＋ `[工具返回]` ＋ 中文答案 | ✅ 2 轮完成 | `01_cli_tool.png` |
| 2 | 对照：不该调就不调 | `--ask "你好"` | 直接回答，**无**工具行 | ✅ 1 轮完成 | `02_cli_plain.png` |
| 3 | 前端解耦 ＋ 过程实时推送 | Web 提问「摄像头里有什么？」 | 依次出现 提问 / 判断 / 调用，**趁工具执行中**截 | ✅ 只见「调用」块，尚未返回 | `03_web_toolcall.png` |
| 4 | 跨解释器桥接 | 同上跑完 | 出现「返回」＋ 答案块 | ✅ 耗时 15890.5 ms，返回 1 个目标 | `04_web_result.png` |

## 三个结论

**① 控制反转真的生效了。**
用例 1 与 2 是**同一份代码、同一份工具表**：问时间会去调 `get_time`，问好则直接回答。
程序里没有任何一处 `if "几点" in ...` 之类的分支 —— 要不要调、调哪个，是模型自己决定的。

**② 前后端确实解耦。**
用例 3 是**工具正在执行时**截的：此刻 YOLO 子进程还在冷启动加载模型，
但界面已经先渲染出「调用」块 —— 说明事件是**实时推送**的，不是等结果返回再一次性渲染。
而 `cli.py` 只是同一套事件的另一个订阅者，`core/` 并不知道谁在监听。

**③ 桥接可用，代价可见。**
用例 4 的 **15890.5 ms** 就是子进程冷启动 ＋ 加载模型的全部开销（热缓存后约 2.5 s）。
做成常驻服务会快得多，但两边就耦合了；现在 `core` 对 YOLO 的存在完全无感。**这是刻意接受的取舍。**

## 已知局限（不阻塞，后续可优化）

用例 4 里模型报「检测到一双鞋」，但实际画面中并没有鞋 —— 置信度 **0.321**，是**误检**。

- **根因在数据，不在代码**：`dataset2` 的 54 张图**张张都有鞋**，没有任何"无鞋"的负样本，
  所以模型没有"背景"这个概念，对陌生物体也会给出 0.1~0.3 的弱响应。
- **佐证**：`exp-2` 的 **precision 只有 0.70**（它自称有鞋的框里约三成是错的），
  混淆矩阵的 `background` 行**整行空白**（验证集里根本没有无目标的样本可统计）。
- **量化**：训练集里的鞋约 **0.70** 分，而摄像头实拍的鞋只有 **0.38** 分，
  与误检的 0.19~0.32 只差约 2 倍 —— **调阈值无法两全**：调高会丢真鞋，调低会放误检。
- **改进方向**：① 补 20~30 张无目标图，配**空标签文件**作负样本 ② 用同一个摄像头在实际场景补拍正样本混入重训。

> 本次验证的目标是「**跑通**」：agent loop 能自主调工具、前后端解耦成立、YOLO 能作为插件接入 ——
> 这三点均已实机达成。误检属于模型泛化能力范畴，与 Harness 架构本身无关。
